设计核心

为什么不是简单的「课表转 ICS」

🕐

钟点不属于课表事实

课程只存「星期 + 节次 + 教学周」。08:00 这类钟点由当天生效的作息表在导出时现算——学期中途换季，数据模型毫发无损。

🧩

不用一条 RRULE 糊弄一学期

重复规则只携带第一个钟点，作息一换整条都错。本项目为每一次实际上课生成独立 VEVENT，几百个事件对现代日历毫无负担，换来逻辑可靠。

🔁

UID 稳定 + SEQUENCE 版本

反复导出同一节课得到同一 UID；内容变了就递增 SEQUENCE——重新导入时日历客户端知道该「原地更新」，而不是无视或翻倍。v0.8 起课程名不再参与 UID 身份，改课名同样原地更新（course_id 缺失的行除外）。

🛡

绝不静默缺课

周次越界报错、解析不了的行拒绝写盘、无法表达的调课默认终止导出。宁可当场失败，也不给你一份「看起来正常、实则少课」的日历。

考试走的是同一套尾部管线：独立的考试快照 + 独立的 UID 配方，撤销条目则对照本地台账（last-exams-<学期>.ics）生成，因此需要上一次发布的留底作 SEQUENCE 基线。

⚠️ 这不是时区 DST。中国全年恒为 Asia/Shanghai。真正变化的是「第 N 节课对应的钟点」——学校的作息规则问题，本项目把两者彻底解耦，导出的 ICS 还按 RFC 5545 内嵌了 VTIMEZONE。
快速开始

三步拿到第一份日历

1

登录（由真人完成）

弹出的是一次独立的浏览器实例（专用用户数据目录）。请在那个窗口里完成统一身份认证， 确认课表正常显示后回终端按 Enter。程序不读取、不记录、不上传任何凭据。

# 安装（PyPI；login 与默认抓取路径都要带上这两个 extras）
pip install "xjtu-timetable-calendar[http,browser]"

# 登录
python -m xjtu_calendar login

会话过期后重登要带 login --force； 窗口里认证过后还会落在「请选择身份」，要点「学生」并等到课表真的显示出来再按 Enter—— 停在身份选择页按 Enter 会得到一份能过认证、接口全 403 的半截会话（doctor 的「会话」一项会指出来）。这一步也别丢给后台任务或管道——终端那句「按 Enter」它们永远等不到，表现就是「看起来成功、其实什么都没做」。

2

获取课表

学期代码自动探测；每次获取都会把上一份快照留作 diff 基线。 HTTP 路径会顺手把「我的考试安排」一起抓进本地快照。

python -m xjtu_calendar fetch \
  --semester 2026-2027-1
3

导出并导入

双击 timetable.ics 即可进 Apple 日历；之后调课了，重导出重导入即可原地更新。 产物默认同时含本学期考试事件（--no-exams 可关）。

python -m xjtu_calendar export \
  --semester 2026-2027-1 -o timetable.ics
想让它自己更新，就再走第四步（可选）：把同一份 .ics 发布成订阅 URL，之后每次课表变化只需 fetch → subscribe push，客户端按 URL 回源，不必再导入。 
python -m xjtu_calendar subscribe init --repo https://github.com/<用户名>/<仓库>.git --semester 2026-2027-1
python -m xjtu_calendar subscribe push --semester 2026-2027-1
入口在哪、各家客户端会有什么不同，见 订阅与客户端选择。
还差一份你自己的校历：「第 1 教学周的星期一是哪天」必须从官方校历确认后填入 ~/.xjtu-timetable-calendar/semesters/<学期>.json——本项目刻意不内置猜测值，填错会整体偏移。模板见仓库 examples/。
卡住了先跑体检：doctor 只读地把版本 / 会话 / 校历 / 作息 / 课表快照 / 考试快照 / 渲染 / 订阅留底一次看全，不写任何文件、默认一个请求都不发；有阻塞项时退出码为 5。 
python -m xjtu_calendar doctor --semester 2026-2027-1 --verify
v0.5 / v0.6

考试安排也进同一份日历

📝

不必再手抄期末

fetch 的 HTTP 路径在抓课表的同时抓「我的考试安排」，export / subscribe push 把考试并进同一份 .ics、同一个订阅 URL。考试是单场绝对时刻的 VEVENT：不用 RRULE、不写 VALARM，提醒交给客户端设置。

🎫

类型词原样带出

标题形如「示例课程甲（期末考试）」，类型词取自接口原文——期中考、结课考，以及「补考」「缓考」都原样呈现，不做白名单。考场在 LOCATION，座位号与课程号、学分、主考教师写在 DESCRIPTION。

🚦

三态判定：状态未知绝不覆盖

「本学期没有考试」和「查询没成功」返回的行数都是空，所以判定落在响应的 extParams.code 上：有考试 / 确认无考试 / 状态未知。未知时宁可沿用旧快照（warning 里报出它是哪一天的）也不覆盖——课程是主功能，考试侧任何失败都不会让 fetch、export 非零退出。

🔻

撤销自动下发（v0.6）

已发布到订阅端的考试若在本次数据里消失（改期、取消、或确认无考试），下一份产物把那条旧事件标上 STATUS:CANCELLED 再发一次，保留到它的原定时刻自然过去。撤销条目只带最小字段——没有考场、座位、教师，也没有课程名。

⚠️ 但「取消」在手机上不一定表现为消失。2026-10 真机演练：Google 日历（网页版）会据此移除日程； Outlook.com 与 ColorOS 系统日历实测忽略 STATUS:CANCELLED，把撤销条目当普通事件导入。 自 v0.6.1 起那条日程带一个固定标题「已取消的活动」（此前是不带标题的「无主题」残条）， 一眼能认出是废弃条目，但不会自动消失，要等原定时刻过去后由下一次发布收掉。 一次性导入型客户端不回源，撤销对它完全无从生效——仍需手动删除。
交付方式

导入一次，还是订阅一条 URL

📥

手工导入

拿到 .ics → 双击导入。简单、零公网暴露，但课表一变就要重新导出、重新导入，多端各来一遍。导入型入口把事件一次性写进本机，此后不再回源，subscribe push 对它无效。

🔗

URL 订阅（subscribe）

把同一份 .ics 发布到你自己的 GitHub Pages（公开仓库 + 不可猜的 token 文件名），客户端按 URL 定期回源。日常更新只有两条命令：fetch → subscribe push，未变动的事件在客户端保持安静，变动的事件原地更新。

🔁

换链接（rotate）

转发给了不该给的人、或有任何泄露疑虑时跑 subscribe rotate：新文件挂上分支、旧文件名从 tip 消失，旧 URL 自此 404。代价是所有客户端都要重新粘贴新 URL。

🏷

日历名从产物里来

不指定 --name 时，标题按课表自动推导成「西安交通大学课表 · 大三-上」；凡是不敢定的情况（自定义学期 key、课表里没有入学年级字段、年级出现并列）一律退回基础名，宁可少信息也不给一个错的年级。年级只影响标题，不参与 UID、不写进事件，所以订阅端不会因为换了名字而重收整学期课程。

客户端行为矩阵（2026-10 真机演练；单账户单样本，别当厂商承诺）

客户端订阅入口收到 STATUS:CANCELLED条目从 feed 静默消失自动回源用 X-WR-CALNAME 命名
Google 日历（网页）其他日历 → 通过 URL 创建移除条目也会移除清理由 UID 缺席驱动，墓碑不是触发条件（2026-10-13 试验田实测）是两次实测延迟分别 ≤3h31m、≤10h05m是（添加那一刻取名）
Google 日历（手机 App）无此入口不适用不适用实测 App 不显示「从 URL 添加」的日历，勾 syncselect、强制同步、走代理都不行

各类「导入日历」选本地 .ics 文件不适用——不再回源，一次性快照否不适用

「条目从 feed 静默消失」这一列是 2026-10-13 在试验田仓库（不是正式订阅）上单独测的： 一份 96 事件的整学期规模产物换成 91 事件，抽掉 5 条不发墓碑、URL 与标题都不动。 Google 网页版截至 T+14h39m 已移除其中 4 条，同批 7 处对照条目全部健在（⇒ 不是"没回源"）； 最后一条（当时距今 58 天的 12-10）在 T+24h58m 的周视图复核里也已消失 ⇒ 5 条全清、对照全在。

分辨自己走的是哪条路：订阅型入口带「上次同步时间」，导入型只有显示开关。 另外，客户端通常在添加那一刻取一次日历名就不再更新：产物后来改了名，已加好的日历未必跟着改—— 退订再重新添加**通常**有效，但本仓库未在真机上验证过改名这一项；而且 2026-10-12 的整学期迁移演练里，ColorOS 上「删除日历 + 重新添加」并**没有**清掉本地产物里已不存在的旧条目——所以别把重加当保证，改完要让用户确认日历确实变干净了。

所以手机侧到底订哪个

  • iPhone / Apple 日历：原生「添加日历 → 订阅」，直接贴 URL；CLI 也会顺手打一行把 https:// 换成 webcal:// 的同址链接，iOS 上通常点开即弹订阅确认——这条本仓库未做真机验证，失败就回手动路径。
  • ColorOS：系统日历里的「URL 日历」就是手机侧正解——认新增、会自动原地更新、并用产物给的日历名。
  • MIUI / 鸿蒙：若系统日历只给「导入日历」，那是一次性快照、永不自动更新；改用 ICSx⁵（at.bitfire.icsdroid）做 URL 订阅。注意不是 DAVx⁵——它只做 CalDAV 双向同步，官方 FAQ 明确把 URL 订阅指向 ICSx⁵。
  • Google 日历：订阅只能在网页版建立，手机端要上课表请走系统日历那条腿，别把希望放在 Google App 上。
  • 给同步器关掉电池优化并允许自启动，否则后台查杀会伪装成「装了但从不更新」。
  • 订阅型日历通常是只读的：没有「删除单条事件」的入口；而那条「已取消的活动」占位是产物自身携带的，忽略取消字段的客户端退订重加时会再导入一遍（2026-10-12 真机实测），所以重加清不掉占位、只能清本地重复项——占位要等原定时刻过去后由下一次发布收掉。反过来，Google 侧连不带墓碑的消失项也会删（2026-10-13 试验田实测）⇒ 过期条目从产物里退场，在 Google 上是一条干净的路。
用之前先把口径读明白： ① 刷新是纯手动的——本工具不做定时任务、不常驻进程，也不会替你 fetch； ② 发布仓库是公开的，匿名浏览分支就能看到 <token>.ics 的文件名， 所以「知道 URL 才能读」这层保护在公开仓库上并不成立——转发 URL 等于授权，任何能浏览该仓库的人都能读到你的课表； ③ 含考试发布时，考试名称、时间、考场以及 DESCRIPTION 里的座位号会进入那份公开产物， 不愿意公开就用 --no-exams； ④ 课程 UID 已升到 v2（0.8.0）：课程名不再参与身份，改课名走原地更新 （course_id 缺失的行除外）；真退课会以 STATUS:CANCELLED 下发。升级到 v2 的那一次迁移只在 subscribe push 自动发生（手工 export 导入者需删旧日历重导一次）， 忽略取消字段的客户端（Outlook.com / ColorOS）会看到一次整学期「已取消的活动」——2026-10-12 整学期 规模真机演练实测 ColorOS：96 条新日程 + 75 条「已取消的活动」占位（1:1 成对）+ 21 条已过原定 时刻的旧条目。这批占位由产物自身携带，退订重加清不掉（会再导入一遍），只能等各自 原定时刻过去后由下一次发布收掉；回滚不免费（退回 0.7.x 会双份）。Google 那条腿未在整学期规模复验（演练 URL 已下线），仍按小规模实测写「通常会移除」。详见 「升级到 v0.8」； ⑤ 发布分支永远是「无父孤儿单提交 + 强推」，课表旧版本不进 git 历史。
自动化 · 体检

配置不用手抄，状态不用猜

📰

notice · 停课/调课通知

解析教务处通知页的调课表格，与校历周次交叉校验后合并进配置——只新增、识别不了的行拒绝写盘。

⏰

schedule · 作息表

从教务处公开「学生作息时间表」页直接读第 1~10 节课两季钟点，切换点取自页面原文，幂等合并。

🔍

diff · 调课检测

纯本地比对两次 fetch 的快照：哪门课新增删除、哪个时段改了周次/教室/教师，并列出「考试变更」（新增 / 取消 / 时间 / 教室 / 座位）。

🩺

doctor · 只读体检

版本 / 会话 / 校历 / 作息 / 课表快照 / 考试快照 / 渲染 / 订阅留底一次看全。不写任何文件、不触发 fetch，默认一个 HTTP 请求都不发（只有 --verify 才对订阅 URL 做一次匿名 GET）。0 = 无阻塞（警告不阻塞）、5 = 有阻塞项，脚本与 Agent 可以直接判定成败。

🧩

skills/ · 交给编码 Agent

仓库根两个技能：xjtu-timetable-setup（八步部署向导，登录一步显式禁止后台执行器与管道，收尾以 doctor 退出码定成败）与 timetable-api-archaeology（给陌生学校的接口考古方法论，含「什么时候该停下来」）。整个目录复制进你所用 Agent 的 skills 目录即可，内容不假设任何特定产品。只想试一次的话，页首有一段可整段复制的提示词。

python -m xjtu_calendar notice   --url <通知页地址> --semester 2026-2027-1 --apply
python -m xjtu_calendar schedule --semester 2026-2027-1 --apply
python -m xjtu_calendar diff     --semester 2026-2027-1
python -m xjtu_calendar doctor   --semester 2026-2027-1 --verify
如实说明一处仍未验证：2026-10-14 已在干净虚拟环境 + PyPI 发布物上把八步逐字 照抄走查过一轮（抓出并修好五处「照抄就跑不通 / 绿灯撒谎」），但真人从零跑第 2 步登录 仍未覆盖——离线环境造不出真凭据。技能文档的「已知边界」写着同一句话。

doctor只读体检，退出码 0 / 5 可直接判定「部署到位没有」默认否

退出码有语义（2=未登录、3=登录失效、4=接口拒绝——最常见是登录停在「请选择身份」的半截会话，见 README 的 403 一条、5=doctor 检出阻塞项），方便脚本串联。完整参数与客户端订阅入口见 README · 命令参考。

隐私与安全

你的数据只属于你

  • 不绕过统一身份认证，不访问他人有权限范围之外的数据
  • 不读取、不记录、不上传任何账号密码
  • 会话与课表只存本地 ~/.xjtu-timetable-calendar/，文件权限收紧到属主可读
  • 日志递归脱敏：cookie、token、学号、姓名绝不输出，订阅 URL / token 也不落日志
  • 所有请求串行、401/403 立即终止不暴力重试
  • 仓库不含任何真实课表数据，测试固件全部脱敏
  • 撤销条目只带最小字段与一个固定标题，没有考场、座位、教师与课程名
  • 考试快照与本地台账含个人信息：只落本地、收紧权限原子写盘、永不发布
  • 课程改名等用户可见的变化会在 diff 里先报出来，再决定要不要发布
订阅通路的例外通道要说实话：subscribe 的风险模型与上面几条不同—— 它把课表放到一个匿名可读的公开地址上，而发布仓库本身是公开的， 匿名浏览分支就能看到 <token>.ics 的文件名。 所以随机 token 挡不住「会看分支列表的人」，转发 URL 等于授权。 配套约束是：发布分支恒为无父孤儿单提交（旧版本不进 git 历史）、强推前有 tree 护栏、 状态文件收紧权限写盘、泄露疑虑时 subscribe rotate 换链接。 不愿意把考试名称、考场与座位号放进那份公开产物，就带 --no-exams。
