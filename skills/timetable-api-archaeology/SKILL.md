# 教务接口考古：方法与停止条件

## 先说清楚这个技能不承诺什么

它**不产出能用的订阅**，也不保证任何一所学校接得进来。它承诺的只有一件事：
**别把已经踩过的坑重新踩一遍**。下面每一条判据背后都是一次真实代价，
来自西交大 eHall 这一家从零到 v0.6 的完整过程；在别的系统上是否成立，
取决于使用者带回来的观测。

自由度是故意留高的：面对陌生系统，能给的只有启发式和停止条件，不是脚本。

## 第 0 步：先停下来问清楚

任何探测动作之前，三个问题必须有明确答案。任一不清楚就**停**，并输出
「我停在哪一步、需要什么才继续」，不要用"先试试看"绕过：

1. **目标学校的条款是否允许程序化访问教务系统？** 很多学校写明不得以脚本、爬虫或
   自动化方式访问。自己爬自己学校给自己排日历，和做一个通用工具让一群人去爬各校系统，
   在条款面前不是一回事——**承担后果的是那些同学，不是写工具的人**。
2. **用的是不是用户本人的账号？** 不是本人账号就停。
3. **用户是否理解抓到的数据落在本机？** 原始响应含学号、姓名、教师姓名、考场座位。

凭据永远由用户本人输入。Agent **不代填、不读取、不保存、不截图**，
也不把会话文件内容打印进对话或日志。细则见 `references/red-lines.md`。

## 第 1 步：观测四问

每一问都要**payload 里的证据**，不接受"看起来是"。清单见
`references/probe-checklist.md`。

### 一问：字段名与语义键能否一一对上

课表行需要这些语义：课程名、教师、教学楼与教室、上课时间片段、周次表达、学分、
学期标识。先把响应里出现的键逐个归到这些语义上，归不进去的记为"未知字段"而不是丢掉。

- 判据：一份真实响应 + 一张 `语义键 → 实际字段名` 的对照表。
- 注意**同一所学校里会有多张表**：课表行的教师是 `SKJS`，考试行的教师是 `ZJJSXM`。
  西交大这两张映射表刻意不共用，因为两个接口的差异是真实的。别为了"看起来整洁"合并。
- 字段名会漂移。本校已经遇到过一次"改名导致解析跳过整行"，所以解析层要保留
  候选名列表与跳过报告，而不是硬编码一个名字。

### 二问：周次是什么形态

三种形态，展开逻辑完全不同：

- **位掩码**（eHall 的 `SKZC`：一串 0/1，每位对应一教学周）；
- **文本**（`"1-8周"`、`"单周"`、`"2-16周(双)"` 这类，需要正则）；
- **日期区间**（直接给每节课的日历日期，那就不需要周次展开）。

判据要具体到"第 3 周有没有课"：拿一份已知某门课只在双周上的样本，看三种形态里
哪个能把它还原正确。**展开错了，产物看起来完全正常，但半学期的日程时刻都是错的。**

### 三问：学期怎么发现、代码格式是什么

有没有"学期列表"接口？当前学期从哪来？代码是 `2026-2027-1`、`2026-2027-01` 还是
`2026fa`？这个字符串会进 UID 和订阅文件名，**改一次就等于换一份日历**。

判据：同一账号连续两次抓取，学期代码字符串完全一致；且它的格式写进了观测记录。

### 四问（go/no-go）：「没有数据」与「查询失败」能否区分

这是唯一的一票否决项，不是打分项。

- 判据：在响应里找一个**能区分二者的信号**——西交大用的是
  `extParams.code == 0` 配合"查询失败"文案；很多系统根本没有这种字段。
- **区分不了 ⇒ 撤销通路在该系统上不可用**，不是"稍差"。原因很硬：
  "空"既可能是真的没有，也可能是抓取失败，任何一侧误判都会
  **撤销掉用户已经发布的整学期数据**。没有这个信号，就不要做增量撤销，
  也不要在报告里写"该校支持撤销"。
- 顺带确认分页：响应行数与响应声明的总数是否一致。不一致说明只拿到第一页——
  本校为此留了一条翻页护栏 warning。**静默截断比报错危险得多。**

## 第 2 步：身份字段决定客户端表现

找一个在"改期、改名、换教室"之后**仍然不变**的字段作为事件身份（接口行 ID、
任务 ID 之类）。西交大考试用 `WID`，缺失时才降级到 `KSRWID`、再降级到内容组合，
每次降级都写日志。

- 选错的后果不是"不够优雅"，是**旧事件永远留在用户客户端里**：
  身份变了 ⇒ UID 变 ⇒ 客户端当成新事件，谁也删不掉那条旧的。
- 判据：同一门课，改一次上课时间再抓一次，比对两次那个候选字段的值。
  值不变才可以用；变了就往下找一个。
- 没有稳定身份字段的系统，只能接受"每次导入都是全新日历"，
  并明确告诉用户这条限制。

## 第 3 步：对照探针——每个结论都要有一个必然可见的变化

这条是一整晚演练换来的，最容易被跳过，也最不能跳过。

**规则**：想判断某个信号有没有生效，必须同时制造一个**一定会被看见**的变化作为对照。
只观察到"什么都没变"就下结论是无效的——它既可能是"客户端忽略了该字段"，
也可能是"我的改动根本没发出去"、"客户端还没到回源周期"。

本校的实际形态：发布两份产物，一份带撤销条目、一份把某场考试的时间改掉。
"时间改了"就是对照；它一旦可见，"撤销条目还在"才是客户端真的忽略 `STATUS:CANCELLED`，
而不是刷新根本没发生。

配套的两条硬约束：

- **刷新周期不可由我们控制，也不可强制**。三家客户端实测最长的回源间隔以小时计，
  且没有"立即刷新"的入口。判断结论前先确认改动**确实发布出去了**
  （URL 匿名 GET 能拿到新内容），别急着怀疑客户端。
- **读不到就写"未验证"**。真机没确认的表现一律写「通常会」并注明未验证，
  不许写成事实。

## 第 4 步：安全停止条件

出现下面任一条，就停下来把情况如实报告给用户，不要继续试：

- 目标学校条款禁止程序化访问，或条款读不出结论。
- 需要绕过验证码、扫码、异地认证，或需要"替用户登录"。
- 第四问（三态可区分性）没有答案，而用户要的是撤销/增量更新。
- 找不到任何稳定的事件身份字段。
- 需要枚举学号、遍历他人课表、并发压接口、或反复重试撞限流。
- 探测要产出"能用的订阅"——那是另一个工程，接口稳定之外还要校历、作息、
  合规与隐私口径全部落地，**不在这次观测的承诺范围内**。

停在这些条件上是**正确结果**，不是失败。把"停在哪、需要什么才继续"写清楚就是交付。

## 已知边界

- 本方法论的全部实证来自**一所学校的一个账号**，跨系统的泛化未经验证。
- 它不包含任何学校的端点、字段名或 URL。带回来的观测请脱敏后再进仓库，
  并说明是哪一年、哪一个接口。
