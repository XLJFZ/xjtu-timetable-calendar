# 西交大课表 → 日历订阅：部署向导

## Overview

把 `xjtu-calendar` 从"装上了"带到"用户手机上能看到会自己更新的课表"。
八步，每步都规定**证据**：拿不出证据就不许宣布该步完成。

## 三条贯穿全程的规矩

1. **不猜任何学校日历数据。** 学期起始日、总周次、作息钟点，工具刻意不内置猜测值；
   猜错的产物看起来完全正常，但整学期时间全是错的。宁可停下来问用户。
2. **只在有证据时说成功。** 判据来自命令输出、文件是否存在、`doctor` 的退出码，
   不来自"看起来没报错"。
3. **绝不接触凭据。** 不读取、不代填、不保存、不截图用户的账号密码或会话文件内容。

## 第 1 步 环境

- 动作：`xjtu-calendar --version`（或 `python -m xjtu_calendar --version`）。
- 证据：版本 ≥ **0.8.5**。这里有四个下限，别混：`doctor` 子命令自 0.7.0 才存在（低于它，
  本向导的收尾判据根本跑不出来）；第 7 步的 v1→v2 迁移语义、以及 `doctor` 的
  「UID 配方与迁移」一项自 **0.8.0** 才有；而第 7 步的**发布失败恢复**（`subscribe repair`、
  退出码 `7` 那道门、`rotate` 与 `push` 共用同一道门）自 **0.8.5** 才有——停在 0.8.0–0.8.4
  的用户会在第 7 步拿到他版本里并不存在的 `repair` 指引。
  **校历事件那一套（`--include-calendar-events`、退出码 `8`、`doctor` 的「校历事件」一格）自
  0.9.0 才有**，而且是**默认关**的可选特性：本向导不主动启用它，用户没提就别碰；
  他要是提了"把寒假也放进日历"，先确认版本再给旗标，低版本给出去只会得到
  `unrecognized arguments`。**判据的最低版本 = 该判据能跑起来的那个版本。**
- 证据（第二条，2026-10-14 走查补）：`python -c "import httpx, playwright"` **两个都要过**。
  基础包只依赖 `icalendar`，`login` 要 `playwright`、默认抓取路径要 `httpx`，都在 extras 里。
  只装裸包的环境 `--version` 是绿的，却会在第 2 步当场报「登录功能需要 playwright」——
  **`--version` 通过不等于能走完本向导**。
- 不满足：`pip install -U "xjtu-timetable-calendar[http,browser]"` 后重新验证（注意带引号，
  `[]` 在部分 shell 里会被解释）；装不上先解决 Python 版本（要求 ≥ 3.11）。
  若版本显示为 0.6.x 而你确定装过更新的包，那是**可编辑安装的元数据没刷新**
  （重跑 `pip install -e . --no-deps --no-build-isolation`），不是 doctor 坏了。

## 第 2 步 登录（必须交回真人）

- 动作：**把命令原样交给用户，让他在自己的前台终端里执行**：
  `python -m xjtu_calendar login`（会话过期时用 `login --force`）。
  交代清楚**窗口里要走到的位置**：认证之后还会落在「请选择身份」页面，必须点「学生」
  并等到课表真的显示出来，再回终端按 Enter。
- 证据（三条都要）：会话文件的**修改时间发生变化**；`fetch` 不再返回 401；
  `doctor` 的「会话」一项**通过**——它数的是会话文件里 `path` 以 `/jwapp` 开头的
  cookie（正常登录 4 条），并且单看一条承重的 `_WEU` 在不在（2026-10-14 消融实测：
  只去掉 `_WEU` 就立刻 403；两份同名 `JSESSIONID` 少任一份都还是 200，
  所以**别把 403 归因到同名 cookie 的取舍上**）。停在身份选择页按 Enter 会得到一份
  "能过认证、接口全 403"的半截会话，前两条证据都还是绿的，只有第三条抓得住（真人踩过）。
  从本次修复起 `login` 自己也会管这一步：按完 Enter 后最多轮询 20 秒等教务侧 cookie，
  没等到**不关窗口**，而是提示补点「学生」再等一轮；收尾那句会打印「N 个 cookie，
  其中教务侧 M 个，含/缺 `_WEU` 票据」，M 为 0 或缺 `_WEU` 时都同时打警告。
  所以判据先看 `login` 自己的输出，
  `doctor` 那条是兜底（用户在追问那一轮按 Ctrl-C 时，会话文件保持原样、不会写坏）。
- 禁止清单（每一条都真实发生过）：
  - 不要放进后台任务执行器或管道（`... | tail`）。它会停在终端等一个 Enter，
    在管道里永远等不到，表现成"卡住"，还会留一个占住会话目录的浏览器窗口。
  - 不要相信"我已经登录过了"。工具用的是**独立浏览器实例**，用户平时浏览器里的
    eHall 登录态对它毫无作用——必须在它自己弹出的那个窗口里认证。
  - 不要相信 `login` 打印的"已检测到本地会话"。不带 `--force` 时它看到旧会话文件就
    直接退出，不看那份文件是否早已过期。
- 那个窗口打开后**什么都不渲染**时才按灰页处置。判据是"窗口里没有可见内容"，
  **不是**地址栏尾巴有没有 `?browser=no`——那是 eHall 服务端在 CAS 回跳时给落地页
  拼上的固定参数，2026-10-08 一次**成功登录**的捕获里它同样在（`/new/index.html?browser=no`
  之后一路 200 打到课表接口），拿它当判据会把好会话误判成坏的。
  处置：先在该窗口地址栏手输终端打印的入口 URL；仍不行就让用户用
  `XJTU_CALENDAR_BROWSER` 指向另一个浏览器。**灰页本身的成因仍未证实**——
  最大嫌疑是后台执行器弄坏子进程 stdio（见 `troubleshooting.md` 同名小节）。

## 第 3 步 学期校历

- 动作：向用户要三件事——**第 1 教学周的星期一**、**总周次**（没有官方数字就留空，
  它是校验上限不是生成依据）、**学期标识**。写进 `semesters/<学期标识>.json` 时，
  文件里的 `semester.key` **必须等于文件名那个标识**（它进 UID，见下）。
- 证据：`doctor` 的「学期校历」一项为通过，**并且把该项打印出来的日期回读给用户确认**。
  这条不是形式主义：这一项原本只判"文件在不在"，把 README 的格式示例
  （`2026-09-07` / 16 周）逐字抄进去也能通过，而真实官方值若是 `2026-09-14` / 18 周，
  产物会**整学期错一周且全程零提示**（2026-10-14 走查实测）。现在 detail 会带出
  「第 1 教学周周一 …、共 … 周」，念给用户听、等他点头，才算这一步过。
  若警告「key 与学期标识不一致」——**别顺手改完就继续**：改 `key` 等于换掉整份日历的
  UID 身份，已经订阅过的人会遇到"旧事件全留下、新事件再来一份"。
- 提醒用户：第 1 教学周的星期一 ≠ 开学报到日，要以学校官方校历为准。
- 一处会把整条向导卡死的地方：`unsupported_adjustments` 只要声明了**且日期落在本学期内**，
  `export` 与 `subscribe push` 都会停手（退出码 `1`）、`doctor` 的渲染项判**阻塞**（`5`），
  而第 8 步的收尾判据正是 doctor 退出码 `0`——等于永远交付不了。
  `examples/academic_calendar.example.json` 里那条演示值已刻意写成 `2099-11-14`，
  照抄整份文件不会撞上；但只要用户（或你自己）把日期换成"看起来更像真的"，就会撞。
  不需要这个字段就删掉整段；确实需要且能接受缺课时，加 `--allow-unsupported-adjustments`
  并如实告诉用户少了哪几个时段。

## 第 4 步 作息表

- 动作：先 `xjtu-calendar schedule` 预览，确认后
  `xjtu-calendar schedule --semester <学期标识> --apply` 才真正合并落盘
  （抓官方作息页，切换点取自页面原文，解析不了的行会逐条列出且拒绝写入）。
  **不带 `--apply` 时它只预览、不写任何文件**（它会自己打印「以上为解析结果预览
  （未写入任何文件）」），照抄不带 `--apply` 的写法永远拿不到本步的证据；
  `--apply` 还必须带 `--semester`（生效区间的覆盖范围来自该学期校历）。
  抓不到就让用户按「必须由你配置的内容 → 2. 作息表」的模板手工填写
  （README 留同名小节作入口，模板内联在 `docs/user-guide/config-templates.md`）——
  那里有可直接抄的完整 JSON；仓库根的 `examples/` 只是它的权威拷贝，
  **`pip install` 出来的环境里没有那个目录**，别把它当成本地路径报给用户。
- 证据：`doctor` 的「作息表」一项为通过。
- 注意夏秋季 / 冬春季两套钟点会在学期中间切换，这是本校的既有事实，不是异常。

## 第 5 步 抓课表

- 动作：`xjtu-calendar fetch`。
- 证据：`doctor` 的「课表快照」通过；渲染项报出的事件数 > 0。
- 若「考试快照」是警告：正常。未排考时接口本来就没有数据，**不要**为此重登或改配置。

## 第 6 步 导出与自检

- 动作：`xjtu-calendar export -o <路径>`，然后**再导出一次**比对 UID。
- 证据：两次导出的 UID 集合一致（这是订阅端能原地更新的前提；变了就说明配置或数据在动）。
- 用 `inspect` 看脱敏结构，用 `diff` 看与上一份快照的差异；解析跳过的条目要逐条向用户复述。
  `diff` 在**第一次 fetch 之后必然报**「[错误] 旧课表快照不存在」（退出码非 0）——
  基线是 fetch 轮转出来的 `*.prev.json`，刚装完还没有。这不是故障，别为此回头重登或重抓；
  要立刻比对就 `--old` 指一份自己留底的 raw。

## 第 7 步 发布成订阅

- 动作：`subscribe init --repo <发布仓库的 git 远端 URL> --semester <学期标识>`
  登记发布目标 → `subscribe push` 发布。
  **`--repo` 与 `--semester` 都是必填**：照抄不带它们的 `subscribe init` 一步都走不出去——
  缺 `--repo` 停在「the following arguments are required: --repo」，
  缺 `--semester` 停在「[错误] 未指定学期」（两处都是退出码 1，不是"配置错了"）。
  `--branch` 默认 `cal`。`--url-base`：**GitHub 公开仓**可以不写（自动推导成
  `https://<用户名>.github.io/<仓库>/`）；**其余一切情形都必须显式给**——
  推导只看"远端是不是 GitHub"，不看仓库是否私有，而私有仓上 GitHub Pages 不提供托管，
  推出来的那条是 404，且 init 不会报任何错。也就是说**按下面推荐的私有仓 + Cloudflare Pages
  走时这条默认要带**（`--url-base https://<项目名>.pages.dev/`），别指望工具替你推。
  漏带的形状要认出来说给用户听：退出码仍是 `0`，订阅 URL 打成
  `https://<用户名>.github.io/<仓库>/<token>.ics`，紧跟着还打印「仓库 Settings → Pages →
  Deploy from branch」那两行 —— 而私有仓上 GitHub Pages 不提供托管，那条地址是 404。
  （0.9.1 及更早版本到这里就没了；下一版起 `init` 会多打一段这个警告。）
  处置照文档：手工把状态文件 `subscribe/subscribe-<学期>.json` 里的 `url_base` 改成
  pages.dev 那个前缀，再用只读的 `subscribe status` 确认；**别**删状态文件重 init，
  那会换掉 token。两种情况下都不要在改好之前把订阅地址交出去。
- 证据：`subscribe status` 显示留底一致，且 `doctor --verify` 的「URL 自检」通过（HTTP 200）。
- 必须如实告知用户两件事，不许淡化：
  1. 订阅 URL 里的随机 token **等价于凭据**，不要提交、不要发到群里；
  2. 若发布仓库是**公开**的，仓库分支页会直接列出 `<token>.ics` 的文件名——
     "知道 URL 才能读"这层保护在公开仓库上并不成立。
- 上面第 2 条有两条出路，本技能**默认推荐路径 B（私有仓 + Cloudflare Pages）**：产物默认把
  考试名称、时间、考场和座位号一起带出去，而 URL 上的 token 是它唯一的门槛——门槛要真成立，
  承载它的仓库就不能对外。（`docs/user-guide/subscription.md` 的「先选一条托管路」把代价列在
  同一屏。）**推荐可以替用户给，注册第三方账号不能替他做**：用户明确要五分钟内跑通、
  并接受发布仓库公开，就按路径 A 走完，别反复劝。B 的两条代价要同屏说清，不许淡化：
  多一个第三方账号，以及 `pages.dev` 在国内**间歇**可达——我方账号 2026-10-21 在 Wi-Fi 与
  移动数据下各拿到过一次真 `.ics`，但"间歇"就意味着换人、换时间点、换运营商都要重验；
  相比之下 GitHub Pages 那条有多条真机读数支撑。
  走 B 时的三个硬约束：
  ① **先 `subscribe push` 再去 Cloudflare 建项目**（建项目时要当场选生产分支，
  而 `cal` 分支是这次 push 才创建的；分支不存在时那个选择框会怎样未实测，别去赌），② 控制台 `Create` 那页的五个选项**全是 Workers**
  （发出来是 `*.workers.dev`，国内基本不通），Pages 在那页**最底下那行小字**里，
  点 "Continue to Pages" 再选 "Import an existing Git repository"；
  ③ 换订阅地址**之前**先让用户在**关掉代理的手机上**打开一次
  `https://<项目>.pages.dev/<token>.ics`（Wi-Fi 与移动数据各一次），拿到
  `BEGIN:VCALENDAR` 才算过——打不开就别换，换了就是静默失效。
  改 `url_base` 本身**不需要也不应该**跑 `push`（跳过条件只看内容哈希与 token，
  换地址推不动任何东西；而隔几天再 push 会因为课表随日期变化而发出一次用户没要的改版），
  用只读的 `subscribe status` 确认即可。
- 换 token（`subscribe rotate`）会让所有已添加的 URL 立刻失效，需用户明确同意。
- iOS / macOS 用户可以**试** init / push / rotate / status 四处打印的那条 `webcal://` 链接
  （它只是把同一行 `https://` URL 换个 scheme）。「点开就弹订阅确认」**没有在本项目真机验证过**，
  只能说「通常」，失败就回手动路径：iOS「设置 → 日历 → 账户 → 添加账户 → 其他 →
  添加已订阅的日历」、macOS 日历 App「文件 → 新建订阅日历」（「iOS / macOS：`webcal://` 订阅链接」
  一节有完整版，在 `docs/user-guide/subscription.md`）。rotate 之后要用**新** token 的那条重订。
- **这一条不改变发布物形态**：`webcal://` 是 URL scheme 而不是文件，发布分支的 tip
  仍然只有**一个** `<token>.ics`。**不要**因为看到 webcal 就去多发布一个 `<token>.webcal`
  文件——那会撞 `subscribe` 的 tree 护栏（根目录恰好一个 `*.ics`）与 rotate 只清 `*.ics`
  的清理逻辑；非 https 的 `url_base` 下工具根本不打印这一行。
- 升级到 v0.8（0.8.0）时如实告知（口径解释，不新增判据）：课程 UID 改用配方 v2、
  课程名不再参与身份，改课名从此走原地更新；首次 `subscribe push` 会自动做一次 v1→v2 迁移
  （发布前打印一行预告），`export` 不参与迁移——手工 `export` 导入的用户需删旧日历重导一次。
  忽略 `STATUS:CANCELLED` 的客户端（Outlook.com / ColorOS）会看到一次整学期「已取消的活动」。
  2026-10-12 整学期规模真机演练实测：迁移在 ColorOS 上表现为 v1 条目被**原地改写**成「已取消的活动」
  （地点清空）、v2 作为**新日程**另起，同一时段 1:1 成对，规模 = 96 条新日程 + 75 条占位 + 21 条
  已过原定时刻的旧条目。**更正旧口径**：这批占位是产物自身携带的，忽略 `STATUS` 的客户端退订重加时
  会**再导入一遍**（实测重加后占位仍在、仍 1:1），所以**退订重加清不掉占位**、只能清本地重复项；
  占位要等各自原定时刻过去、从产物里退场，**而 ColorOS 连退场项都不清**（同批 21 条旧条目在删除日历
  再重新添加之后仍在），这条通路上等不到自动清理；换到 ICSx⁵ 之后退场项会被 prune 掉（2026-10-19 实测）。
  Google 那条腿**未在整学期规模复验**（演练 URL 已下线），
  仍按小规模实测写「通常会移除」。
- 订阅步骤的提醒：Google 侧栏里同校同学期的**演练/临时订阅与正式订阅会同名**（日历标题由课表数据
  推导，只有 URL 里的随机 token 不同）。用户同时挂着两份会分不清——提醒他**给日历改名**或注意同名，
  别误删正式那一份。
  若 push 报退出码 `6`（疑似没抓全的整批撤销被熔断拒绝），先 `diff` 确认再决定是否带
  `--allow-mass-cancellation` 放行。
  若报退出码 `7`（本地发布状态与「最后一次已发布的版本」不相容），**先跑
  `subscribe repair`** 再重跑 push，别直接带 `--allow-unverified-baseline`：它会拉回线上
  真实字节，在「已发布凭据」与「待发准备稿」之间裁决，把本地对齐回去，**不产生新发布**。
  退出码 `7` 也出现在 `subscribe rotate` 上，两处是同一道门（rotate 的补发与 push 共用
  同一条发布事务，门排在换 token **之前**——所以被拦住时 token 还没换、旧 URL 依旧好用）。
  若报退出码 `8`（**0.9.0 起**，校历事件的发布准入），处置**只有改配置**这一条：
  `--include-calendar-events` 带着发布时 `events` 有错或有未裁决的 `conflicts`，或者上一版
  发布过校历事件而这次漏了那个旗标。它与 `repair` 无关，也不接受任何 `--allow-*` 旗标。
  校历事件**默认关**，没带旗标、也从没发布过它的人不会碰到这一码。
  旗标**管不到两格**：「上一次发布的结果还没裁决」（准备稿还在）与「凭据读不懂」——
  强行继续会把那份待裁决的准备稿覆盖掉，此后无从判断线上是哪一版；这两格只有 `repair`
  （或先修好那份文件）。
  从 0.8.5 之前升级上来**不需要**任何旗标（留底与发布记录相符时会自动放行，
  只打一条"台账未能校验"的警告）。只有一种情况 `repair` 会如实失败并报「仍有本地状态
  无法恢复」：那次发布"不该动"的台账被删了、或当时没有后来凭空多出一份——它的**内容**
  没被记进凭据，补不回来。

## 第 8 步 选客户端

读 `references/client-matrix.md` 再给建议。核心决策只有一条：
**要自动更新就必须走订阅型入口**；"导入日历"是一次性快照，之后任何变更与撤销都收不到。

**安卓的默认建议只有一个：装 ICSx⁵（`at.bitfire.icsdroid`，免费获取地址
`https://f-droid.org/packages/at.bitfire.icsdroid/`），不分 ROM。** 别带着用户在系统日历里
找订阅入口——MIUI / 鸿蒙常常只给「导入日历」那一项；也**不是 DAVx⁵**（它只做 CalDAV 双向同步，
遇到 Webcal 是把 URL 转交给 ICSx⁵，自己不拉纯 HTTP 的 `.ics`）。统一走一条通路比按机型摸索可靠。
告诉用户 `f-droid.org` 在国内网络下实测不可达，下载环节通常要挂代理。

只有 ICSx⁵ 确实装不上时才退回系统日历自带的订阅入口（它的成本是真实的：商店版按我方口径收费、
直下 APK 要允许未知来源、国内网络下 `github.com` 与 `f-droid.org` 实测不可达通常要挂代理），
并且必须把该客户端缺的语义讲清楚再交付——例如 ColorOS 的「URL 日历」会回源并原地更新，
但忽略 `STATUS:CANCELLED`、消失项不删、单条删不掉。

## 收尾：一条命令定成败

```bash
xjtu-calendar doctor --verify --semester <学期标识>
```

退出码 **0** 才算交付完成；**5** 表示还有阻塞项，回到对应步骤解决。
**1** 是另一回事：多半没指定学期（`--semester` 或环境变量 `XJTU_SEMESTER` 二选一），
不是"体检没过"。
警告（`[警告]`）不阻塞，但要向用户逐条解释它意味着什么。
「校历事件」那一格（0.9.0 起）**与发布门共用判据**，所以它也接 `--include-calendar-events`：
不带 = 问"普通 push 会被拦吗"，带了 = 问"我打算这么发，检查一遍"。用户没启用这特性时不要
因为他配置里躺着一段坏 `events` 就宣布部署失败——那一格会喊，但门对他放行（新门不拦没用它的人）。
**不许在阻塞项未清时说"应该没问题了"。**
「订阅」一项判阻塞时只有一条出路：**先跑 `subscribe repair`**（它按线上真实字节把留底、
两份台账与迁移标记对齐，不产生新发布），修完再 `doctor`。这一格与 `push` 的退出码 `7`
是同一条判定的两张脸，别再往登录或校历上折腾；体检仪自己**不代跑修复**，所以
`repair` 得你按命令跑。唯一的例外是"从 0.8.5 之前升级上来、本地没有恢复凭据"那一格，
它是警告不是阻塞（直接 push 会自行补回依据）。

## 已知边界（必须原样告诉用户）

- 本向导**只做过一轮离线全新安装走查**（2026-10-14：干净虚拟环境 + PyPI 发布物 +
  隔离 home + 本地裸仓库，八步逐字照抄）。它抓出了 extras、`--semester`、校历 `key`
  等五处卡点并已修；但**真人从零走一遍仍未做过**——尤其第 2 步登录需要真凭据，
  离线走查覆盖不到"用户在窗口里实际会停在哪一页"这一类卡点。
- 客户端行为矩阵是**单账户单样本**的实测，不是厂商承诺；客户端会改版。
- 撤销条目在忽略 `STATUS:CANCELLED` 的客户端里不会消失，只会变成一条写着
  「已取消的活动」的日程；它是否会随产物退场而清理，**尚未验证**。
