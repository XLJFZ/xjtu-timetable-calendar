## 1. 背景与目标

用户 2026-10-21 提出：把思源学堂（LMS）的作业 DDL 也写进日历。
当晚做了一次只读取证，数据形状比预期干净，故先立此规格把决策点摊开，**不代表已决定要做**。

目标（若批准）：让**未提交作业的截止时间**出现在订阅日历里，并在提交之后从日历上退场，
不需要用户手工删。

红线：不为了这个功能把"两个源给出互相矛盾的考试"引进来（见 D6 与 §5 第 2 条）。

## 2. 取证摘要

原始现场记录在本地 gitignored 的笔记里（不入库，因为里面有真实课程号与作业标题）。
**本节已经包含接手所需的全部形状**，那些字段都按本仓库的口径做了脱敏：课程号只保留学期前缀、
作业标题与课程名一律不写。

`GET https://lms.xjtu.edu.cn/api/todos` → 顶层 `{"todo_list": [...]}`，取证时 **21 条**，
每条 11 个字段：

| 字段 | 形状 | 说明 |
| --- | --- | --- |
| `course_code` | `202620271COMP…`（真实后缀已脱敏） | **学期号 + 课程代码拼成**，前缀 `202620271` = 2026-2027 第一学期 ⇒ 自带学期 |
| `course_id` | 数字 | 课程内部号 |
| `course_name` | 中文串 | 身份字段，不入库 |
| `course_type` | 数字 | 含义未查 |
| `end_time` | `2026-10-31T15:59:00Z` | **UTC**；同一时刻界面显示「2026.10.31 23:59」 ⇒ 差整 8 小时 |
| `id` | 7 位数字 | **作业的稳定 id**（本议题 UID 配方的锚点） |
| `is_locked` | 布尔 | 含义未查 |
| `is_student` | 布尔 | 本次全 `true` |
| `prerequisites` | 数组 | 本次全为空数组 |
| `title` | 中文串 | 作业标题，身份字段，不入库；**但它会进日历产物**（见 D7） |
| `type` | 字符串 | 本次 21 条**全是 `homework`**，取值全集未知 |

四条实测结论（这四条是判据，不是推断）：

1. **一个 GET 出全量**，URL 上没有分页参数。**但会不会截断未验** —— 样本只有 21 条，上限未知。
2. **有稳定 id，且 `course_code` 前缀就是学期号** ⇒ UID 用 `hw:<course_code>:<id>` 时，
   「跨学期撞号」这个 v0.8 迁移的根因天然不存在。
3. **`end_time` 是 UTC**：同一条数据的两个表示法对得上就是 UTC。方向别写反 —— 截止时刻本身是
   东八区 23:59，接口只是序列化成 `T15:59:00Z`；**把串里的 15:59 当上海墙钟用会提前 8 小时到期**。
   「都在 23:59 截止」只是这一条样本看到的，其余 20 条的钟点分布未取，不许写成 LMS 规则。
4. **没有「已提交 / 未提交」状态字段** —— 列表本身就是"还没交的"，提交后该条
   **静默消失**而不是变成 CANCELLED。这是本议题最核心的语义。

公告那一支走的是独立端点：`/api/announcement` 与 `/api/bulletins/latest` 当时都回 200 且数组为空
⇒ 字段形状未知，不许推断。也正因如此，「作业 + 考试 + 公告」不是一个接口选三种 `type`，
而是至少两到三个端点，字段不同、消失语义不同，成本按端点数乘算。

复跑方法（在自己已登录 `lms.xjtu.edu.cn` 的浏览器标签页里，从控制台发同源 GET；
只读取数据，别点任何提交类按钮）：

```js
// ① 列出页面加载过的 XHR 端点（有些浏览器自动化通道在这类页面上录不到请求，
//    performance 资源表是可靠的那条）
() => { const x = performance.getEntriesByType('resource')
  .filter(r => ['xmlhttprequest', 'fetch'].includes(r.initiatorType));
  return JSON.stringify(x.map(r => r.name).slice(0, 40)); }

// ② 取 /api/todos 的形状，中文串（课程名 / 作业标题）自动打码
async () => { const j = await (await fetch('/api/todos', {credentials: 'include'})).json();
  const arr = j.todo_list || []; const first = arr[0] || {}; const proj = {};
  for (const [k, v] of Object.entries(first)) {
    if (v === null || typeof v === 'number' || typeof v === 'boolean') proj[k] = v;
    else if (Array.isArray(v)) proj[k] = 'arr[' + v.length + ']';
    else if (typeof v === 'object') proj[k] = JSON.stringify(v).slice(0, 90);
    else proj[k] = /[\u4e00-\u9fa5]/.test(v) ? '<zh str len ' + v.length + '>' : v;
  }
  return JSON.stringify({n: arr.length, keys: Object.keys(first), first: proj,
    types: [...new Set(arr.map(o => o.type))]}); }
```

## 3. 范围

**只做 `type=homework`。** 考试与公告**明确排除在本期之外**，理由不是"没时间"，是
各自缺一条决定性读数且缺口性质不同：考试缺"是否与门户排考重复"的样本（此刻 LMS 里
一条考试都没有），公告缺字段形状（端点返回空）。把未验语义接进一条已经干净的数据源，
是本项目反复付过代价的那类错误。

## 4. 决策点（逐条待用户拍；括号里是代理的建议，不是结论）

**D1｜UID 配方。** 建议 `hw:<course_code>:<id>`。依据：`course_code` 自带学期号 ⇒
跨学期撞号这个 v0.8 迁移的根因天然不存在；`id` 是稳定数字。（**待拍**：要不要像课程那样
把配方版本号写进 UID，以便将来改配方时能再走一次迁移。）

**D2｜事件形态：DDL 是瞬时点还是占一格。** RFC 5545 允许 `DTSTART == DTEND`（零时长），
但**零时长事件在各客户端怎么显示，本项目一次都没验过**（现有产物里只有全天事件与带时长的课）。
（**待拍**：建议先按"占 30 分钟、落在截止时刻"做，因为它不需要任何未验的客户端行为。）

**D3｜时区。**（2026-10-21 补读数，本节原判据不变。）先钉住一条容易写反的方向：接口字段是
**UTC 序列化**，而不是"上海墙钟减了 8 小时"。同一条数据在 `/api/todos` 里形如
`end_time = "<日期>T15:59:00Z"`，界面上同一时刻显示成「当天 23:59」——两个表示法相差整 8 小时，
所以字段带 `Z` 这条自证成立。真正的写错方向是**把串里的 15:59 当成上海墙钟直接用**，
那样每条作业提前 8 小时到期、看起来"已经截止"；不是延后到次日。
（"截止都是本地 23:59"只是**一条样本**看到的；其余 20 条的 `end_time` 分布未取，
不许当成 LMS 的规则写进解析逻辑——解析必须按字段给的瞬时点换算，见下。）

现有产物的既有约定是：事件引用 `TZID=Asia/Shanghai` 并内嵌 `VTIMEZONE`
（`src/xjtu_calendar/exporter.py` 的 `add_missing_timezones` 一支，`X-WR-TIMEZONE` 同处）。
落点已核实：`exporter.py` 直接把 `item.start` / `item.end` 交给 `component.add("dtstart", ...)`，
时区由那个 datetime 自带的 `tzinfo` 决定；构造时间统一走 `schedules.combine(day, "HH:MM")`
（`tzinfo=TZ_XIAN`，刻意不接收 naive、不读系统时区）。⇒ LMS 那条要做的是
`datetime.fromisoformat(end_time).astimezone(TZ_XIAN)` 拿到**带上海时区的 aware datetime**，
再进现有管线；把 aware UTC datetime 直接递进去会被写成 `TZID=UTC` 或 `...Z`，那才是本条要拦的。
这条换算在本机实测过：`<日期>T15:59:00Z` → `<日期> 23:59:00+08:00`（用项目自己的
`xjtu_calendar.timeutil.TZ_XIAN`，`requires-python >= 3.11` ⇒ `fromisoformat` 认尾缀 `Z`）。
顺带一条兜底证据：在一台**没装 `tzdata`** 的解释器上跑，`timeutil` 走到了它文档里那条末路分支，
拿到 `timezone(timedelta(hours=8), 'Asia/Shanghai')`，`tzname(None)` 仍是 `Asia/Shanghai`
⇒ 写进产物的 `TZID` 不会因本机缺 tzdata 而变化。
（本条不需要拍，照抄现状即可，写在这儿是为了防止实现时图省事。）

**D4｜消失即退场：发墓碑还是直接不发。** 这是本议题真正的新问题——作业不是"被取消"，是"被完成"。
§8 已回答"已过原定时刻的条目不发墓碑"，但那一条的前提是过期；**"用户提交导致源里消失"不在
§8 覆盖范围内**。（**待拍**，两个方向各有代价：直接不发 ⇒ 依赖客户端 prune，ICSx⁵ 真机成立、
ColorOS 永不删；发 `STATUS:CANCELLED` ⇒ 日历上会出现一批"已取消的作业"幽灵，正是今天那 69 条
墓碑的形态。建议：**先取 §5 第 4 条读数再拍**。）

**这一条今天多了一条新代价（2026-10-21 追加，见 followups §13 补记第 5/7 条）**：手表这类
**手机的下游镜像设备**上，"消失项会不会被清"一次都没验过，而现有那批 `STATUS:CANCELLED` 墓碑
**已经顺着"feed → 手机 → 手表"这条链在手表上留了一份**（手机界面看不到）。⇒ "发墓碑"这一支的代价
不止"手机上多一批幽灵"，而是**幽灵会沿着镜像链往下游扩散，且每往下一层就少一个可用清理入口**；
反过来"不发、只靠消失"这一支也**不能只按手机端的 prune 成立就当数**。这两支都要按下游设备重判一遍。

**D5｜开关。** 需要独立的 `--no-homework`，**不得复用 `--no-exams`**（那个只管门户考试快照）。
默认并入还是默认不带？（**待拍**；注意默认并入意味着老用户下次 push 会**突然多出 N 条**，
这属于用户可见产物变化，要走版本号判断，见 D8。）

**D6｜考试那一支（本期不做，但把红线先钉住）。** 若将来接，必须用**不同 UID 前缀 + 独立开关**，
且要先有"同一场考试两个源的时刻是否一致"的样本。最坏形态不是日历上多一条，
而是**两个源给出不同时间**，用户不知道该信哪条。

**D7｜隐私口径。** 作业标题会进那份匿名可读（现为私有仓 + URL 即凭据）的产物。
现有口径是"产物里有什么就是公开什么"，考试那支为此配了 `--no-exams`。
（**待拍**：作业标题是否视为可公开；不公开的话 D5 的开关就是必选项而非可选项。）

**D8｜版本与迁移。** 新增数据源 + 默认并入 ⇒ 用户可见产物变化，按仓库口径要进 minor 版本；
且第一次带作业发布时，`SEQUENCE` 与台账的行为要照 §12 那次的教训先彩排一遍。

**D9｜登录态接进 CLI。** LMS 是**第二个独立会话**。门户的 `login` 是交互式的（源码里有
`input()`，AGENTS.md 第 8 条），思源这一支怎么登录、凭据存哪儿、过期怎么提示，
**都要在实现前定**，否则会出现"fetch 一半成功一半 401"的新状态。

（2026-10-22 补一条实测：失败形态**不是 401**。不带任何 cookie 打 `/api/todos` 是
`302` 两跳到 `identity1.xjtu.edu.cn` 的登录页、最终 **HTTP 400 + HTML**，页面标题是英文，
`fetcher.LOGIN_PAGE_MARKERS`（`fetcher.py:68-78`）九条**零命中**，而 `fetch_via_http` 的 401 分支
（`fetcher.py:391-392`）也接不到 ⇒ 落到非重试的通用错误（`fetcher.py:424-427`），
用户读到的是"接口返回 400"而不是"请重新登录"。
这条只覆盖"完全不带 cookie"，**带过期 cookie 的形态未测**，不许外推。
另外两件事决定 D9 的形状：`Endpoint.url()` 把 `cfg.ehall_base` 写死在拼接里（`fetcher.py:105-107`）、
`auth.load_cookies()` 按 eHall 域名过滤并把其它域的 cookie 丢掉（`auth.py:418` 与 `:425-427`）——
现在这一支还发不出请求，不是配置问题，是结构问题。）

## 5. 前置读数（取不到就不许写实现）

1. **`type` 取值全集** —— 现在只见过 `homework`；等某门课在思源上发测验时复跑取证脚本。
2. **思源课程考试与门户排考是否重复** —— 依赖第 1 条先有样本。
3. **LMS 会话能维持多久** —— 被动复测：下次未登录状态下直接打 `/api/todos` 看 200 还是 401/302。
   （2026-10-22 取到**一半**：不带 cookie 时是 `302 → 400 + 登录页`，见 D9 的补记；
   "带过期 cookie" 与"会话能撑几天"这两半仍空。）
4. **零时长 / 短时长事件在 ICSx⁵ 与 ColorOS 上的显示** —— 决定 D2。
   （2026-10-22 收窄：**"零时长"那一支不用去客户端取证就已经出局**——
   `models.CalendarEvent.__post_init__` 是 `if self.end <= self.start: raise ValueError`
   （`models.py:314`），`DTSTART == DTEND` 连构造都过不去。
   于是这条读数的问题变成"30 分钟窗口 vs 全天"，而且全天那一支另有代价（D4 的墓碑通路
   不收全天事件，`cancellation.py:66-69`）⇒ D2 与 D4 不是两个独立的问题。）
5. **`todo_list` 会不会截断** —— 待办数明显变多（如期末）时复测。
6. **`end_time` 的钟点分布** —— 本次只逐条看过第一条（`...T15:59:00Z` ⇔ 界面「23:59」），
   其余 20 条未取，所以"作业都在本地 23:59 截止"是**样本观察，不是 LMS 规则**。
   **这条不承重**：D3 的解析本来就按字段给的瞬时点换算，不假定钟点；取不到也不拦实现，
   记在这儿只为了拦住"把 23:59 硬编码成判据"这种写法。
7. **门户 `login` 建的那个本机 profile 里，有没有 LMS 域的 cookie** ——（2026-10-22 新增，**承重**）
   两边 IdP 名字不同（Keycloak realm `xjtu` + CAS broker vs 门户侧 CAS），但可能是同一套 SSO。
   答案决定 D9 是"复用 `login` + 一次静默访问"还是"多一个 login 入口"。
   取证成本：跑一次 `login` 后数 `session/storage_state.json` 里的 cookie 域名，cookie 值不进任何文档。
8. **`todo_list` 回空数组时，是"全交完了"还是"会话/权限异常"** ——（2026-10-22 新增，**承重**）
   第 3 条的前半已取到（未登录时回 400 + 登录页，见 D9 的补记），但那是"完全不带 cookie"，
   而 `200 + 空数组` 这一种形态一次都没测过。
   **不切开这条，D4 两支都不许开工**：10A（消失即不发）等于"一次会话异常把用户所有作业事件
   从日历抹掉"，10B（发墓碑）等于"凭空发一批已取消的活动"。
   解析侧的 `UNKNOWN` 兜不住这一种，因为它的结构是完全合法的。

## 6. 明确不做

- 本期不接考试、不接公告（§3）。
- 不做"提交状态"追踪：LMS 没有这个字段，做不了。
- 不把 LMS 数据写进门户那条 `fetch` 的 raw 快照（两个源、两套失效，混在一起会让
  相容性检查与 `repair` 的裁决依据变模糊）。
- 不在本议题里重开 §12（搬到过去时段）。

## 7. 一句话结论

数据这一侧是干净的（稳定 id、自带学期、单一端点全量），**卡住这件事的是语义而不是接口**：
作业是"完成即消失"的东西，而"消失"在本项目里从来不是一个客户端通用的概念——
§8、§12、§13 三处账都记在它身上。所以下一步不是写代码，是取 §5 那八条读数里最便宜的承重项。

3. **那份实施计划骨架不要直接执行**。它是按"本仓库来实施"的假设写的，任务边界、门禁与派发预算都绑着
   本仓库的 `AGENTS.md`；换一个人接手，绑不绑这套纪律只有他自己知道。

已经替你量过、可以少跑两轮的：

- **ICSx⁵ 会把从产物里消失的条目清掉**（2026-10-19 真机判过），所以"交完自动退场"这条通路在手机上是通的。
- **ColorOS 原生订阅永不删消失项**（同批真机判过），所以同一份产物在 ColorOS 上会留下已交作业，
  和本仓库今天那批已取消课程的残条是同一类问题，只是规模更小。
- `STATUS:CANCELLED` 的处置在不同客户端差异很大，见 `docs/design/2026-10-11-subscription-followups.md` §13。
- **没量过的**：零时长事件（`DTSTART == DTEND`）在各客户端怎么显示——本仓库产物里从来没有过这种事件，
  所以 D2 那个建议（占 30 分钟）就是为了不去碰这条未验行为。

两条红线不要顺手跨过：

- 作业标题会进那份可能被匿名读到的 `.ics`（订阅通路的风险模型见 README 的「隐私与安全」与
  `docs/user-guide/subscription.md`，本议题里它是 D7）。
  要接就先决定放不放标题、放什么形式，别默认"反正是我自己的日历"。
- 思源的作业与门户的考试是**两个源**。将来若真接考试，必须不同 UID 前缀 + 独立开关，
  不许复用 `--no-exams`（那一个只管门户那一支）。
