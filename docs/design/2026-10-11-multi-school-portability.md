# 多系统 / 多校可移植性 — 议题备忘

日期：2026-10-11　状态：**议题备忘，不是规格**。没有排期，不承诺实现。
来源：v0.6 演练收尾后的一次讨论（"这套东西能不能推广到别的学校和别的教务系统"）。
关联：`docs/design/2026-10-07-url-subscribe-ics.md`（订阅通道）、
`docs/design/2026-10-08-exam-schedule.md`（第二个数据源怎么接进来）、
`docs/design/2026-10-11-subscription-followups.md`（客户端侧议题）。

---

## 0. 结论先行

**现在不动。** 可移植性的瓶颈不在代码结构——结构已经分好层了——而在两件事：
一是**没有第二家的真实接口观测**，此时画的任何抽象边界都是猜的；
二是**合规与隐私的风险量级会随泛用性上升**，那不是工程问题。

真要往这个方向走，第一步不是写 adapter，是照 §6 做一次只读观测。
拿到第二家的真实 payload 之后再回来读这份备忘，§3 的三档方案才有得选。

---

## 1. 耦合面实测：比想象中集中

`src/xjtu_calendar/` 合计 **8998 行**（`wc -l` 实测）。真正写着"西安交通大学 / eHall"的部分：

| 模块 | 行数 | 与学校的关系 |
|---|---|---|
| `fetcher.py` | 596 | 端点调用、登录主机白名单（`fetcher.py:73-75`）、401 与登录页判定 |
| `parser.py` | 558 | 课程行的字段候选表 `FIELD_CANDIDATES`：**14 个语义键 / 41 个候选字段名** |
| `exams.py` 的解析段 | — | 考试行字段表 `EXAM_FIELDS`：**13 键 / 17 候选名**，外加 `KSSJMS` 四种时间形态 |
| `notices.py` + `schedule_notice.py` | 1016 | 抓教务处通知页与作息页（HTML 结构、切换点取自页面原文） |
| `weeks.py` 的位掩码段 | — | `parse_week_mask` 认的是 eHall `SKZC` 那种 0/1 串；同文件的周次**文本**解析是通用的 |
| `config.py` 的默认值段 | — | `DEFAULT_EHALL_BASE`、`DEFAULT_APP_ID`、`XJTU_*` 环境变量族、学期代码格式 `YYYY-YYYY-N` |

**与学校无关的是其余六千多行**：校历与作息的节次展开、`models`、`sequence`
（UID / SEQUENCE / LAST-MODIFIED 的增量语义）、`exporter`、`subscribe`、`diff`、
撤销通路、台账、脱敏日志。也就是说"抓取层"和"日历化层"的分界本来就存在，
**这不是一个糊成一团的爬虫**。

一个必须记住的设计事实：字段映射有**两张表，且刻意不共用**
（`exams.py:52-54` 的注释写明原因：课程表按课程写，teacher 认 `SKJS`，考试行是 `ZJJSXM`，
而且报错文案写死「课程」）。将来做 profile 化时会诱惑人去合并它们——那是错的，
两张表的差异反映的是两个接口的真实差异。

## 2. 三个卡点，只有第一个是工程问题

**① 接口考古是真实成本，而且是永久成本。** 西交大这一家，我们才需要：三态判定
（`code:0 / 查询失败` 到底是"没排考"还是"没查到"）、`KSSJMS` 的四种形态、翻页护栏、
`WID` 身份稳定性、学期发现接口、`SKZC` 位掩码。换一所学校这一整套重来，而且
**对方没有 API 契约、没有变更通知、没有 SLA**——本项目已经为"字段名变了要往
`FIELD_CANDIDATES` 补一条"踩过一次。多支持一所学校 = 多一份脆弱面 × 每学期一次的变动概率。

**② 登录方式各家不同，但机制通用。** 现在是 Playwright 持久化 profile +
`storage_state`（见 `auth.py`），这套本身不绑定学校；要改的是入口 URL、主机白名单、
以及 CAS / 统一身份 / 扫码 / 验证码这些流程差异。注意 `login` 是**交互式**的
（终端要真人按 Enter），这条约束跨学校不会消失。

**③ 合规与隐私的量级跳变——这条最重要，也最容易被"再支持一所学校"的兴奋盖过去。**
自己爬自己学校的教务系统给自己排日历，和做一个通用工具让一群人去爬各校教务系统，
在学校的自动化访问条款面前不是一回事。泛用性做得越好，越可能撞到目标学校
"不得以程序方式访问教务系统"的条文，而**承担这个后果的是那些同学，不是发布工具的人**。
任何跨校推广之前，先把这一条查清楚，并且把它写进 README 的风险口径，而不是藏在脚注里。

## 3. 三档方案的代价

**第一档：把"学校"变成配置（profile 化）。** 一个 source profile 装 base URL、应用 ID、
端点表、两张字段映射、周次编码方式、登录主机表；西交大是第一份 profile。
技术上顺——`data/ehall_endpoints.json` 已经外置、`FIELD_CANDIDATES` 与 `EXAM_FIELDS`
已经是映射雏形、`XJTU_EHALL_BASE` 已经是环境变量。
**但它能走多远完全取决于第二家是不是同族系统**：同一厂商的教务套件，profile 够用；
不同族，profile 会退化成"每所学校一段 if"，比 adapter 更难维护。
**这一档的判据**：第二家的响应 JSON 拿到手，如果字段名换个键就能对上，走这档；
如果需要新的结构假设（嵌套层数、分页方式、时间格式族），直接跳第二档。

**第二档：抽 `SourceAdapter` 接口。** 最小方法集大概就是
`discover_semester()` / `fetch_timetable()` / `fetch_exams()` / `login()`，
西交大做成第一个实现，按名字注册。**这是架构变更，要单独出规格**，
而且要照 v0.5 接第二个数据源那次一样付三轮评审的学费——那一次暴露了
"两个数据源共享同一份快照口径 / 同一个 UID 域 / 同一条裁剪逻辑"这类假设会被静默打破。
接口一旦定了，`diff`、`sequence`、`subscribe` 不许再往 adapter 里漏学校专有概念。

**第三档（不建议）：由一个人内置并维护十几所学校的 adapter。**
那是给自己签无限期苦役合同，而且每所学校的用户都会带着"你为什么不修我这边的"来找你。
如果真要走到多校，正确的形态是**社区各自提交并维护自己学校的 profile / adapter**，
本仓库只保证接口稳定与产物层质量——这又要求第二档先做扎实。

## 4. 一条已经存在、但**不顶用**的接缝

`fetch --from-file <本地 JSON>` 看起来就是"别人写抓取、我们做日历化"的接口，
**实际上不是**：它喂进来的仍然要过同一个 `parser`，也就是必须长成 eHall 那个形状
（`datas.xskcb.rows[]`、`SKZC` 位掩码、`KCM`/`SKJS`/`JASMC` 这套键名）。
它是离线调试入口，不是交换格式。

如果将来真选"我们只做日历化这半截"的路线，**这里才是要做接口契约的地方**：
一份稳定、有版本、有校验报告的中间格式（课表行 + 考试行 + 学期与校历元数据），
让外部抓取器产出它。它的合规面也最小——我们这一侧完全不碰任何学校的服务器。
代价是新增一个要长期维护的公开格式契约。

## 5. 更现实的推广路径

如果目标其实是"让同学也能用上"，那**同校同系统的人现在就能自助**：README 的安装、
`login`、校历与作息配置那一套是完整的，边际成本接近零。这条路不需要任何架构改动。

跨校则是另一个产品，不是这个产品的下一步。真要推，先问自己：想推的是**工具**，
还是"稳定 UID + SEQUENCE + 撤销通路 + 订阅发布"这套**做法**？后者不需要支持任何
学校的接口就能被别人学走，也不需要我们承担 §2③ 的风险。

---

## 6. 真要动，第一步长什么样

**做一次只读观测，不写一行生产代码。** 照 `scripts/probe_ehall.py` 当年的路子：

1. 拿到第二家的课表接口响应（真实账号、只读、一次），存成脱敏样本；
2. 回答四个问题，每个都要有 payload 里的证据：字段名与语义键能否一一对上（→ §3 第一档）；
   周次是位掩码、文本还是日期区间；学期怎么发现、代码格式是什么；
   **"没有数据"和"查询失败"能不能区分**——这一条是三态判定的命根子，
   区分不了的接口，撤销通路（v0.6）在那边就是**不可用**的，不是"稍差"；
3. 顺手确认那所学校的条款允不允许程序化访问（§2③）。

**能推翻本备忘结论的证据**只有一类：第二家的观测显示它和 eHall 属于同一套系统族
（同厂商、同字段命名风格、同分页与错误约定）。那样第一档就够，可以立刻动手。
反之，只要第 2 步里"没有数据 vs 查询失败"区分不了，就应该停下来，
而不是给那所学校特判一条降级路径。

---

## 7. 明确不做的事

- 不在有第二家观测之前抽 `SourceAdapter`、不建 profile 文件、不写"多校支持"的 README 段落。
- 不为了"看起来通用"把两张字段映射表合并（理由见 §1）。
- 不把 `--from-file` 当公开接口承诺——它是离线调试入口，形状随 eHall 变（§4）。
- 不做中心托管服务、不代持任何人的凭据、不内置任何学校的账号入口（既有红线，见
  `docs/design/2026-10-07-url-subscribe-ics.md` 的隐私口径）。
