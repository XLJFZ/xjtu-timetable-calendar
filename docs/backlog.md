# 后续工作候选清单

更新：2026-10-28。基线：0.10.4。

本清单集中记录后续可以开展的工作，优先级是建议顺序，不代表已排期或下一版承诺。
开展前先核对当前实现、测试和设计记录；历史计划里的未勾选框不能直接视为未完成。

## 优先验证

### 1. 跨学期发布与恢复的隔离

- 在同一个临时数据目录内配置两个学期，用本地裸仓库演练交替发布、单侧 rotate、发布中断及 repair。
- 分别验证不同仓库、同仓不同分支，以及误用同一发布分支的情况；后者先查清实际后果，再决定是否增加配置冲突护栏。
- 验收：操作一侧不会无提示地覆盖另一侧的远端产物、本地留底、台账、恢复凭据或重新编号计数器；不支持的配置有明确说明或拒绝判据。
- 来源：[订阅后续记录 §10](design/2026-10-11-subscription-followups.md)。这里补验证，不预先认定已有缺陷。

### 2. 当前版本的新用户完整走查

- 从隔离安装、复制配置、手动登录到首次发布，分别核对两条托管路径的说明与实际输出。
- 覆盖缺依赖、漏配置、会话过期、错误学期、默认缓存缺失及指定输入文件等入口。
- 验收：能按公开文档完成首次使用；错误提示提供可执行的下一步，不依赖开发者本机残留文件。
- 登录须由用户在前台完成；离线走查不能冒充真实账号及手机端到端验证。

### 3. 补齐客户端行为的真机证据

- 优先补 iOS/macOS 的 webcal 入口、订阅刷新与更新表现，以及已有记录仍标未验证的撤销、误删恢复边界。
- 记录客户端版本、测试日期、初始状态、操作顺序和观察结果；单账户单样本结论保留限定。
- 验收：客户端矩阵能区分已测、未测与推测；没有设备或独立试验田时保持待验证，不据此改产物格式。

## 可考虑的工程改进

### 4. 结果与部分成功的结构化表达

- 评估为抓取、发布和体检增加机器可读结果：区分课表更新成功、考试沿用旧快照、无变化、需要重新登录及发布结果待裁决。
- 先设计兼容的字段和退出码策略，不直接改变现有考试失败降级语义。
- 验收：调用者无需解析中文日志即可判断完整成功、部分成功及所需人工动作；既有 CLI 行为有明确兼容边界。
- 此项是独立候选，不因本机定时更新暂缓而自动启动。

### 5. 发布事务的组合故障覆盖

- 在已有崩溃恢复测试上，盘点尚未覆盖的组合：时间剪枝与另一份台账异常、换 token 与重新编号、首次发布与未知远端结果、连续修复中断等。
- 每个缺口先复现；已有覆盖直接复用，避免重复堆测试。
- 验收：发布结果未知时保留裁决依据，恢复后再次发布的 UID、SEQUENCE、台账与计数器一致；所有序列使用合成数据与本地仓库。

### 6. 多学期使用便利性

- 在第 1 项验证后，再评估列出已配置学期、按学期查看订阅状态，以及换学期配置检查与明确提示。
- 保持「一个学期一个订阅 URL」的现有边界；不默认切换当前学期、不自动覆盖另一学期配置，不承诺多学期合并订阅。
- 验收：用户能看清正在操作哪个学期、发布到哪里，以及换学期还缺哪些配置。

## 暂缓

### 7. 本机定时 fetch → push

- 用户于 2026-10-28 评估后决定先不做，不排期、不创建计划任务；继续手动更新。
- 已确认的复杂度包括登录续期、考试部分成功、重复抓取导致的时间戳变化、互斥与超时、通知和恢复策略。
- 只有用户重新提出时再启动；届时先做可手动试跑的自动更新入口，再评估接入系统计划任务。
- 完整评估见[订阅后续记录 §17](design/2026-10-11-subscription-followups.md)。

- 跨校适配：没有第二家的真实接口观测前不做抽象扩展，见[议题备忘](design/2026-10-11-multi-school-portability.md)。
